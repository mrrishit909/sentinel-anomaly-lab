# Data contracts

Every published artifact has a JSON Schema (draft 2020-12) in `data/contracts/<name>.schema.json`, generated by `uv run python -m pipelines.contracts` (source: `pipelines/contracts.py`). `uv run python -m pipelines.validate_artifacts` validates every file in `site/public/data` against its schema. TypeScript types for the site are generated from these schemas.

All artifacts: `schema_version: "v1"`, a `tags` object (honesty tags per field group, pattern `OBSERVED|DERIVED|PREDICTED|SIMULATED|SYNTHETIC`, combinations joined by `/`), compact JSON with sorted keys, no NaN. Each stays under about 400 KB gzip.

| Artifact | Purpose |
|---|---|
| `meta.json` | Provenance, licence and attribution text, splits, metric parameters, detector catalogue (with quantization constants), window index, artifact byte sizes |
| `facts.json` | Single source for every number quoted in site copy: `values[key] = {value, tag, unit}` |
| `channels.json` | 17 channel dictionary and train statistics, quantization ranges |
| `incidents.json` | The 200 labelled incidents with split, per-detector detection and delay, and attribution per incident |
| `detector_eval.json` | Per detector, three val-tuned operating points evaluated on val and test (point, point-adjusted, event), average precision, PR curves |
| `threshold_sweep.json` | Per detector columnar counts at 160 thresholds for val and test; the threshold lab reads this |
| `attribution.json` | hit@1, hit@3 against the dataset's channel labels, random baseline, per root-cause channel |
| `quality.json` | Data-quality check results |
| `reconciliation.json` | Row ledger, label reconciliation against metadata, raw file checksums |
| `overview.json` | 600 s max-pooled scores and anomaly fraction across the whole timeline |
| `window_<id>.json` (12) | One incident window: 17 channels and 5 detector scores at 1 Hz |
| `recompute_vectors.json` | Parity vectors for browser recomputation of metrics from stored scores |

## Encodings

- Typed arrays are base64 of little-endian `uint16` (`labels_u8` and `anomaly_frac_u8` are `uint8`). `encoding` fields name the format.
- **Score quantization.** `q = round(65535 * clip(log1p(s / c) / smax, 0, 1))` per detector; `c` and `smax` are in `meta.detectors[id].quant`. Raw score is `c * expm1(q / 65535 * smax)`. Thresholds are integers in the same `q` domain; the rule everywhere is `flag = q >= threshold_q`.
- **Channel quantization.** `v = lo + (q / 65535) * (hi - lo)` using `channel_range`.
- Sentinel: `delay_median_s = -1` in columnar arrays and vectors means "no detected segment". In row-style objects it is `null`.

## Metric definitions (shared by Python reference and browser)

Parameters in `meta.metric_params`: `merge_gap_s = 30`, `tol_after_s = 60`.

- **Point-wise:** TP, FP, FN on `flag` vs label.
- **Point-adjusted:** for every true segment `[s, e)` containing at least one flagged point, count all `e - s` points as TP (FN otherwise); FP is unchanged. Known to inflate recall and F1; both are always shown.
- **Alerts:** maximal runs of flagged points; runs separated by at most `merge_gap_s` unflagged points merge.
- **Event recall:** a true segment is *detected* if any flagged point lies in `[s, e)`.
- **False alert:** an alert that overlaps no `[s, e + tol_after_s)`.
- **Alert precision** = non-false alerts / alerts. **False alerts per day** = false alerts / (rows / 86400).
- **Detection delay:** first flagged point in `[s, e)` minus `s`, seconds, over detected segments.

## Versioning

Breaking change to any schema means `schema_version` bumps to `v2` and a new schema file; the site pins `v1`.
